# selti-sync — ZCode-плагин автозаписи проектов в selti

Плагин регистрирует git-воркспейс в реестре selti (`POST /projects/register`)
в момент, когда в проекте появляется ссылка на git-репозиторий. Реестр питает
«облачко знаний» (глобальный хук `knowledge-cloud`), которое раньше приходило
только вручную зарегистрированным проектам.

Дизайн — ADR-018 (`docs/ADR-018-selti-sync.md`): идемпотентный POST без GET,
вся логика матчинга (slug / repo_url / local_path) на сервере. Node 18+,
ноль зависимостей.

## Два триггера

| Событие | Matcher | Роль |
|---|---|---|
| `SessionStart` | `startup\|resume` | старт/возобновление сессии. **resume оставлен осознанно**: это легитимная догоняющая регистрация — кейс alexa 28.09 (origin появился через 20 минут после старта ночной сессии, зарегались при утреннем авто-resume) |
| `PostToolUse` | `Bash` | ленивая догоняющая регистрация **внутри живой сессии**: `git init` / `git remote add` выполняются именно Bash-командами — плагин не ждёт следующего старта, а проверяет после каждой из них |

## Алгоритм (общий для обоих событий)

1. `ZCODE_PROJECT_DIR` → `slug` = basename папки.
2. **Быстрый путь**: кеш-маркер `~/.zcode/selti-sync/registered.json` —
   JSON-карта `{ "<workspacePath>": { "repo_url": "...", "ts": <epoch ms> } }`.
   Запись свежая (<24ч TTL) → тихий exit **без git-вызова** (~5мс): обычная
   цена PostToolUse — один readFileSync + JSON.parse.
3. `git remote get-url origin` (таймаут 2с). Не-git папка или клон без
   origin → тихий exit: реестр не замусоривается.
4. `POST {selti}/projects/register` с телом `{slug, name, kind: "code",
   local_path, repo_url}` (таймаут 3с).
   - **201** → записать маркер + одна строка в контекст сессии
     `selti: проект «albedo» зарегистрирован в реестре (slug albedo)` —
     только на SessionStart; на PostToolUse — тишина (сессию не засоряем).
   - **200/409** → записать маркер, молча.
   - любая ошибка → молча и **без маркера** — повтор на следующем событии.

Смена origin (`git remote set-url`) догоняется после истечения TTL либо при
следующей перерегистрации: маркер не сверяет URL с git в быстром пути —
иначе быстрый путь невозможен; чужая/устаревшая запись замещается при
очередной регистрации.

## Журнал

`~/.zcode/selti-sync/sync.log` — строка на каждое срабатывание:

```
2026-09-28T10:34:11.512Z post_tool_use slug=alexa outcome=201
2026-09-28T10:34:12.100Z post_tool_use slug=alexa outcome=skip-marker
2026-09-28T10:40:00.001Z session_start  slug=albedo outcome=no-origin
```

Исходы: `no-origin` (не-git / нет origin), `skip-marker` (быстрый путь),
`201` / `200` / `409` (ответ сервера), `error:...` (сеть/таймаут/HTTP —
без маркера, повтор позже). При превышении 512КБ журнал обрезается до
последних 100КБ (по границе строк).

## Ответы сервера

| Код | `status` | Значение | Хук |
|---|---|---|---|
| 201 | `created` | slug свободен — проект создан | маркер; строка в контекст (SessionStart) |
| 200 | `matched` | slug+repo_url уже в реестре, nothing to do (no-op не трогает `updated_at`) | маркер, молча |
| 200 | `path_updated` | обновлён `local_path` (переезд папки) либо путь перепривязан к своему slug | маркер, молча |
| 409 | `slug_conflict` | slug занят **другим** repo_url — нужен человек (автосуффиксы запрещены) | маркер, молча (случай виден в sync.log и логах сервера) |
| 401 | — | неверный/отсутствующий `X-SELTI-KEY` | без маркера, молча |
| 422 | — | невалидное тело (kind вне code/infra/domain/workspace/org) | без маркера, молча |

## Производительность

- marker-hit (обычный PostToolUse после первой регистрации): readFileSync +
  JSON.parse, git и POST не вызываются — единицы миллисекунд.
- marker-miss: git (~100мс; 2с — только потолок) + опциональный POST (3с
  потолок) — в лимит таймаута хука 10с укладывается с запасом.

## Установка

Локальный plugin-workspace (плагин живёт в репо selti, дистрибуция — через
git, marketplace-публикации нет):

- ZCode: Settings → Plugin Management → добавить локальный плагин из
  `E:\Projects\Python\selti\zcode-plugin-selti-sync` (либо прописать в
  workspace-конфиг `plugin-workspace`).
- Проверка: Settings → Plugin Management → selti-sync → хуки SessionStart и
  PostToolUse помечены runnable.

## Конфигурация

Переменные окружения (приоритет) или файлы в `~/.zcode/` — как у хука
`knowledge-cloud`, конфиг общий на хост:

| Источник | Значение | Файл-фолбэк |
|---|---|---|
| Адрес сервера selti | `SELTI_URL` | `~/.zcode/selti-url` |
| Ключ записи | `SELTI_API_KEY` | `~/.zcode/selti-key` |

Дефолт адреса — `http://localhost:8000`. Если на сервере задан
`SELTI_API_KEY` (env), каждый POST обязан нести заголовок `X-SELTI-KEY`;
пустой ключ на сервере — эндпоинт открыт (LAN-режим).

Файлы (если используются) — одна строка значения, читаются при каждом
срабатывании:

```
~/.zcode/selti-url   → http://10.0.0.51:8000
~/.zcode/selti-key   → <секрет>
```

## Тесты

- Чистая логика — node-тест: `node --test tests/test_selti_sync_hook.mjs`
  (из корня репо selti): basename, TTL-истечение маркера, mismatch repo_url,
  no-marker, формирование и обрезка журнала.
- Ручные проверки (без прода): `SELTI_URL=http://127.0.0.1:9` → exit 0 молча;
  не-git папка → exit 0 молча, в sync.log `outcome=no-origin`.

## Известные ограничения

- Облачко знаний новому проекту приходит со **следующей** сессии
  (knowledge-cloud может прочитать реестр до нашей регистрации) — ADR-018,
  graceful degradation.
- Смена repo_url при живом свежем маркере не детектится до истечения TTL
  (цена быстрого пути без git-вызова) — через ≤24ч перерегистрация
  выправит запись.
- Конфликт «две машины, один repo_url, разные local_path» на этом уровне
  не решается (последняя запись выигрывает) — матч облачка идёт по
  local_path конкретной машины.
