## 1. Как устроены алгоритмы связей (документация — także docs/GRAPH_LINKS.md, фаза E)

**Рождение.** Связи пишет Тишь при грануляции: в `metadata.links` каждой гранулы —
массив `{type, target, description}`. `target` — либо полный UUID, либо entity_name
(строка). Ручные связи — тулом `memory_link` (пишет в `relations` напрямую).

**Синхронизация** (`sync_links_to_relations`, дергается на каждом store/update/ingest_batch,
non-fatal): DELETE связей с пометкой `synced_from='metadata.links'` (ручные не трогаются)
→ INSERT заново из `metadata.links` (BACKFILL_RELATIONS_FROM_METADATA). Дедуп по
(source_id, target_id, link_type). Правило владения: metadata.links = источник истины
для синхронизированных связей.

**Резолвинг цели.** `target` резолвится в UUID только если строка — валидный UUID;
иначе пишется в `target_name` как висячая связь по имени. Следствие: связи с
entity_name-целями НЕ соединяют узлы графа (граф строится по id) — часть «серости»
и пустоты именно отсюда.

**Чтение.** `get_relations_unified($id, $link_type)` — хранимка, UNION incoming/outgoing.

**Кластеризация (Level 2).** beat `refresh_clusters`: Qdrant ANN-соседи +
min-label propagation (миграция 022) — тематические кластеры, отдельные от связей.

**Сироты.** Гранула без единой связи в `relations`. Причины: (а) Тишь не всегда кладёт
metadata.links; (б) target по entity_name не резолвится в UUID; (в) сосед ещё не
существует на момент синка и не до-синкается потом. Замер 2026-09-19: ~4.1k сирот
из ~14.7k гранул (~28%).

## 1.1 Алгоритм связей v2 — диагноз и архитектура (Эна, полное исследование:
**docs/GRAPH_LINKS_V2_ARCHITECTURE.md** — ложится в фазы F2/F3)

Ключевой вывод Эны: граф серый не потому, что связи «плохо ставят», а потому, что
**сервер принимает entity_name в target, но не резолвит их** (UUID-only regex в
BACKFILL/SYNC, queries.py:601/647). Тишь Вынуждена писать имена для forward-ссылок
(UUID будущих гранул она знать не может) — ~40–50% links с именами-целями.

Три генератора серости (подтверждены кодом):
- **Г1** — нет резолва имён в синке; reconciler-задачи не существует;
- **Г2** — тайминг батчей: цель из следующего батча на момент синка не существует, до-синка нет;
- **Г3** — dedup-пути store (UPDATE/SKIP, service.py:166–183) не вызывают sync вовсе.

Пайплайн v2 (L1–L4): **L1** lateral-резолв имён в момент синка (свой проект →
глобальный → свежейшая); **L2** reconciler — beat nightly по готовому
`idx_relations_target_name` + резолв-на-лету при store; **L3** инварианты —
anti-inverse дубль-фильтр, версионная непрерывность (supersede переносит рёбра —
сейчас дыра: FK SET NULL рвут граф); **L4** OrphanLinker. Формула уверенности связи:
`confidence = P_source × S_sem × F_status × B_confirm` → живёт в существующем
`relations.weight` (без миграций).

**OrphanLinker** (фаза F2): выборка сирот (importance DESC) → Qdrant ANN кандидаты
(θ=0.85, k=5, кластеры как booster) → фильтры (CNLM-матрица, asserted, без дублей,
сирота↔сирота разрешены) → LLM-вердикт (пороги обкатанного auto-linker:
≥0.90/0.85/0.80) → INSERT от третьего владельца auto_linker (НЕ через metadata.links,
НЕ с меткой synced). Кап ≤2 связи/сироту; идемпотентность — вердикт-кеш + Redis-маркер.
Стоимость кампании 4.1k сирот: ~410 LLM-вызовов, ~12M input токенов единовременно.

## 3. Фазы

### Фаза A — Контакт соседей: цветные и разные (0.5–1 день; Сона)
Бэкенд (аддитивно, без миграций):
- `models.py Relation`: `neighbor_namespace/neighbor_entity_name/neighbor_content/neighbor_importance` (optional).
- `queries.py`: `GET_NEIGHBORS_INFO` — `SELECT id, namespace, importance, metadata->>'entity_name', left(content,140) FROM memories WHERE id = ANY($1::uuid[])`.
- `pg_repository.get_relations`: собрать id соседей (target для outgoing, source для incoming), один батч-SELECT, разложить поля по связям.
Фронт:
- `graph.ts`: `ensureNode` берёт neighbor-поля → label (entity_name → content-голова → короткий id), namespace (цвет слоя), importance (размер).
- Проверка: серых сателлитов не остаётся; Firefox-скриншот дизайна.
Acceptance: в графе у ВСЕХ узлов цвет слоя и осмысленная подпись; размер = importance.

### Фаза B — Состояние переживает вкладки (0.5 дня; Сона)
- Один глобальный стор (`zustand/middleware persist`, sessionStorage): query/фильтры/страница поиска + query графа + id открытой карточки.
- `useUrlSync`: hydrate только если стор пуст (первый вход за сессию), иначе URL ← стор.
- Acceptance: набрал запрос → ушёл в Проекты → вернулся: запрос и страница на месте; граф хранит свой q.

### Фаза C — Багфиксы (0.5 дня; Сона)
- F2: GranulePanel «Открыть в Графе» → `/ui/graph?id=<uuid>`; GraphScreen: если есть `?id=` — fetch /api/memories/{id} (узел-центр) + /relations (окрестность), поиск-строку предзаполнить entity_name.
- F4: placeholder-переполнение в Firefox: `.searchbox input::placeholder { text-overflow: ellipsis; overflow: hidden }` + на графе placeholder короче («Запрос…») или font-size меньше; проверка в Firefox обязательна.
- F8: фильтр по entity_type в поиске (чипы/дропдаун: function/class/module/sql_query/…, значения — из фактической базе; REST-параметр `entity_type` аддитивно) + бейдж типа на карточке гранулы. База уже показывает: function ×1696, class ×954, module ×2799 — они есть, их надо сделать видимыми.
- Acceptance: кнопка ведёт в граф от этой гранулы; Firefox — ничего не вылезает; поиск «показать только классы» работает.

### Фаза D — 3D-паутина (3–4 дня; Сона + Эна по архитектуре; на декларацию Мастера)
- Библиотека: `3d-force-graph` (three.js; sigma.js 3D не умеет). Ленивый чанк.
- **Звёзды.** Гранула = светящаяся звезда, но строго в палитре Deep Lumen: ядро — цвет слоя (те же --sl-* оттенки спектра), ореол — радиальный градиент того же hue с падающей альфой (аддитивный блендинг), яркость ореола = score. Размер = importance. Разноцветность — из спектра слоёв, никаких цветов вне палитры. Фон — --sl-bg-abyss с лёгкой звёздной пылью (те же 36 частиц с лендинга, дорисованные в 3D).
- **Связи — красивые:** тонкие кривые (пружинная дуга), полупрозрачные, цвет — градиент от цвета источника к цвету цели; hover подсвечивает связь и её концы, остальные гаснут до 12%. Толщина = weight связи.
- **Глубина хопов (F9).** Слайдер 1–5 + режим «Вся карта»: full-map строится прогрессивно (обход /api/graph + батчи relations), узлы за пределами глубины агрегируются в кластерные звёзды (одна звезда = кластер, размер = суммарный count, цвет = доминирующий слой); раскрытие кластера по клику. 14.7k гранул в сыром виде не рендерим — только через агрегацию.
- Управление: орбит-камера (drag/zoom/pan), клик по звезде → GranulePanel, двойной клик → расширить окрестность узла (+1 hop), «Полёт к» из поиска.
- Данные: тот же seed-пайплайн (поиск → relations), кап по умолчанию 300–500 узлов; LOD/деградация: > 500 узлов — рёбра дальше 2 hop не рисуются.
- Переключатель 2D/3D на экране Графа (2D остаётся для слабых машин).
- Acceptance: 300 узлов — 60 fps на интегрированной графике; звёзды цветные/разных размеров; клик → карточка; Full Map строится за < 30с на 15k гранул.
- Риск: WebGL в Firefox/IAB — проверить и fallback на 2D.

### Фаза E — Документация алгоритмов (0.5 дня; Тиамат)
- `docs/GRAPH_LINKS.md`: жизненный цикл связи (рождение → синк → чтение), роли metadata.links vs memory_link vs ручных, резолвинг target, сироты, кластеры Level 2. Источник раздела 1.

### Фаза F — Сироты и связи v2 (2–3 дня; Сона + Нора + Тишь; ПО РЕШЕНИЮ МАСТЕРА)
Мнение Афины: слепое удаление сирот — вредно (сирота ≠ мусор: это знание без связей).
1. **F1. Связи v2** (по GRAPH_LINKS_V2_ARCHITECTURE, ~1.5 дня; Сона+Нора): lateral-резолв имён в синке, beat `link_reconciler`, sync после dedup-UPDATE, перенос связей при supersede, anti-inverse; миграция 023 — после аудита дубликатов entity_name (Нора).
2. **F2. OrphanLinker** (по разделу B архитектуры, ~1 день; Сона): кампания 4.1k сирот (≈410 LLM-вызовов, ~12M токенов) + steady-state beat nightly; dry_run первым прогоном, выборка Мастеру перед массовым применением.
3. **F3. GC по критериям** (после F2; расширить lifecycle_tasks): удалять гранулу-сироту если ОДНОВРЕМЕННО age > 90д ∧ importance ≤ 2 ∧ access_count = 0 ∧ frozen = false ∧ нет кластера. dry_run месяц (как gc_superseded).
4. **Миграция висячих target_name** (по разделу C архитектуры): аудит → точный резолв → версионные цепочки → fuzzy с LLM-арбитром → окно 30 дней → ретракт безнадёжных.
- Acceptance: сироты < 10%; висячие target_name → ноль (кроме отчётных); ни одной удалённой «живой» гранулы; graph_stats_unified до/после.

### Фаза G — Контент реестра (0.5 дня; Тишь)
- Заполнить description/links 7 проектов через PATCH /api/projects/{slug} (микро-грануляция README).

## 4. Порядок и параллель
A → B → C — одним махом (Сона, ~2 дня). D — параллельно после A (Эна + Сона). E/G — Тиамат/Тишь в любой момент. F — старт после декларации Мастера по критериям GC.
