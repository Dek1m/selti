## 2. Допущения и договорённости

- **Имена флагов в кейсах — предположительные** (по конвенции `linker_*`/`edge_*` из `config.py`). Финальные имена фиксирует Сона в коде; тесты наследуют фактические через `Settings(**overrides)` (паттерн `linker_config()` из `test_linker_v3.py`). Предполагаю:
  - `edge_reinforcement_enabled: bool = True`
  - `edge_decay_lambda_base: float = 0.02` (1/день), `edge_decay_lambda_floor: float = 0.002`
  - `edge_prune_threshold: float = 0.05` (raw w_eff), `edge_prune_min_age_days: int = 30`
  - `edge_reinforce_delta: float = 0.2`, `edge_restore_delta: float = 0.5`
  - `traverse_activation_enabled: bool = False` (Ф2, включается после приёмки)
  - `linker_l1c_gate: float = 0.75`, `linker_l1c_gate_fail_open: bool` — решает Эна
- **Математика (вердикт Эны, закрывает Д1/Д2/Д5):**
  - ленивая проекция: `w_eff = weight × exp(−λ_eff × days_since(COALESCE(last_used_at, created_at)))`;
  - `λ_eff = GREATEST(0.002, 0.02/(1+used_count))`;
  - **БД-вес не гниёт**: decay — проекция чтения, идемпотентность по построению
    (повторный расчёт без reinforce даёт то же число);
  - **материальный батч decay УДАЛЁН из плана** — beat-кампания делает ТОЛЬКО
    pruning: raw `w_eff ≤ 0.05` и возраст ≥ 30 дней, иммунитеты
    (manual/l2/inherited_from/frozen), мосты — иммунитет от pruning;
  - reinforce: `weight = LEAST(1.0, weight + 0.2×(1−weight))` — хебб-добавка
    (закрывает Д5), **одно касание за проход**;
  - restore: `pruned_at = NULL` + `weight = LEAST(1.0, weight + 0.5×(1−weight))`
    (0.05 → 0.525).
- **Числа-эталоны** в кейсах пересчитаны Python-проверкой по формулам выше
  (ред. 2, 2026-09-23). При смене дефолтов Эной — пересчёт по тем же формулам,
  структура кейсов не меняется.
- **Живой БД в юнит-сьюте нет** (как в `test_linker_v3.py` / `test_memory_v3.py`):
  SQL-контракты — инвариантами на текстах констант `queries.py` и тексте
  миграции 026 (`Path(...)`-паттерн `MIGRATION_023` из `test_memory_v3.py`);
  поведение — юниты на `mock_pool`; живой SQL — **репетиция на ephemeral PG и
  прод-дампе — ВЫПОЛНЕНА 23.09, протокол DIAG_026_REHEARSAL_2026-09-23.md,
  все пункты зелёные** (оставшиеся стендовые кейсы — только на новых сборках).
- **Тест даты:** все decay/pruning-кейсы на фиксированных датах

## 5. Фаза 2 — traverse(strategy="activation")

### 5.1 Эталон PPR: ручной граф 6 узлов («на бумаге»)

Топология (неориентированная проекция, веса 1.0): рёбра `S—A, S—B, A—C, B—C, C—D, D—E, E—C`. Seed = `{S}`, damping d=0.85, переход из узла равновероятный по соседям проекции.

Персонализированный PageRank: `r_{k+1}(j) = 0.85·Σ_i r_k(i)·P(i→j) + 0.15·e_S(j)`.

- **r1** (из r0=e_S): S=0.15, A=0.425, B=0.425, C=0, D=0, E=0 (Σ=1)
- **r2**: S=0.15, A=0.06375, B=0.06375, C=0.7225, D=0, E=0 (Σ=1)
- **Стационар** (цикл C—D—E—C): S=0.1500, A=B=0.06375, **C=0.2809, D=0.2388, E=0.2030** (Σ≈1)
- 15 итераций попадают в стационар с допуском ±0.02 (остаток затухания 0.85¹⁵≈0.087).

Порядок в топ-K: **C > D > E > S > A = B** (seed S — на 4-м месте: активация расходится от старта, это не BFS-порядок).

### 5.2 Кейсы

## 8. Дыры дизайна Д1–Д8 — ЗАКРЫТЫ вердиктами Эны (ред. 2, 2026-09-23)

> Статус на ред. 2. Кейсы выше уже отражают решения; история для трассировки.

1. **Д1 (математика floor vs pruning) — ЗАКРЫТА.** Материальный батч decay удалён из плана вовсе: w_eff — ленивая проекция чтения (`w_eff = weight×exp(−λ_eff×days)`, `λ_eff = GREATEST(0.002, 0.02/(1+used_count))`), БД-вес не мутируется. Pruning-решение — по raw w_eff ≤ 0.05 + возраст ≥ 30 д: противоречия «floor ≥ порога» нет — floor стал свойством λ_eff-насыщения, а не clamp записи. Кейсы Ф1-LAZ-*, Ф1-PRN-01/02.
2. **Д2 (идемпотентность decay) — ЗАКРЫТА.** Идемпотентность по построению: проекция чистая, повторный расчёт того же ребра в тот же день даёт то же число; «двойного затухания» не существует — мутировать нечего. Кейсы Ф1-LAZ-05/06.
3. **Д3 (restore vs partial unique) — ЗАКРЫТА.** Статус-колонки НЕТ вовсе — только `pruned_at` (решение Норы в 026, совпало с вердиктом Эны; репетиция подтвердила схему). Unique остался безусловным `(source_id, target_id, link_type) WHERE target_id IS NOT NULL` — restore и DO UPDATE-воскрешение не плодят дублей. Кейсы Ф1-MIG-01/03, Ф1-PRN-04.
4. **Д4 (мосты, NULL-кластеры, гонки) — ЗАКРЫТА.** Мост = `cluster_id IS DISTINCT FROM cluster_id` **с NOT NULL-гвардом**: NULL-конец — не мост (не бессмертит), оба NULL — не мост. Гонки с `assign_clusters` нет: мост-список фиксируется на момент прогона кампании, порядок beat не критичен. Кейсы Ф1-IMM-03/04/05/10.
5. **Д5 (reinforce не восстанавливает weight) — ЗАКРЫТА.** Хебб-добавка при reinforce: `weight = LEAST(1.0, weight + 0.2×(1−weight))`, одно касание за проход; restore-таска — добавка ×0.5. Кейсы Ф1-RNF-01..04, Ф1-PRN-03.
6. **Д6 (висячие рёбра) — ЗАКРЫТА.** `target_id IS NULL` (2171 legacy на проде) — в иммунитете pruning-кампании; отдельная кампания позже (после резолва имён). Кейс Ф1-IMM-09.
7. **Д7 (PPR: направленность и as_of) — ЗАКРЫТА по направлению, ОСТАЛСЯ ОТКРЫТЫЙ ПОДПУНКТ.** PPR на неориентированной проекции (симметризация CSR). **Открыто Эне:** способ симметризации пары рёбер A→B/B→A — `max(w)` или сумма. activation + as_of: боевой путь `as_of=now()` только, исторический — 400. Кейсы Ф2-PPR-09 (DESIGN-SYM), Ф2-ERR-04.
8. **Д8 (встречное направление mutual) — ЗАКРЫТА.** Канонизация пары `least/greatest` до upsert: встречная встреча укрепляет существующее ребро, встречное не создаётся. Кейс Ф3-MUT-02.
9. **Замечание тестировщика (ред. 1, остаётся в силе):** для первой недели прода — раздельные флаги `edge_decay` (неактуален после ленивой проекции) → теперь фактически `edge_prune_enabled` отдельно от reinforce: prune выключен, наблюдаемость dry_run-отчётов до необратимых pruned_at. Дёшево, снимает риск первой кампании на 106k строк.
