## 0. Философия в одну строку

Галактика — это **волна плотности** (теория Лина–Шу): рукав не набор тел, а полоса, где звёзды замедляются и сгущаются. Мы строим волну (места), а звёзды (гранулы) садятся в неё со своими гауссовыми скоростями. Детерминизм — «квантовый»: у каждой звезды свой seed (hash её id), коллапс волновой функции всегда даёт одну и ту же позицию.

## 1. Космогония: структура галактики

Единицы: условные координаты плана (bbox [-1000, 1000]³). Радиус диска R_disk = 900, гало до R_halo = 1600.

### 1.1 Спиральные рукава (диск)

Логарифмическая спираль — как у реальных спиральных галактик:

```
r(θ) = a · e^(b·θ),   a = 120,  b = 0.28        (pitch angle = arctan(b) ≈ 15.6° —
                                                     честный диапазон реальных галактик 12–20°)
θ ∈ [0, θ_max],  θ_max = ln(R_disk/a)/b ≈ 7.2 рад  (~1.15 витка на рукав)
```

**N_arms = 4** (при 1753 кластерах ≈ 430 кластеров на рукав — рукава плотные, как в EVE; 2 — пусто, 3 — асимметрия без выгоды). Рукав k — та же спираль, повёрнутая на Δk = 2πk/4.

Гауссовы дисперсии вокруг точки кривой (тонкий диск с flare — утолщение к краю, как у настоящего звёздного диска):

| Величина | Значение | Смысл |
|---|---|---|
| σ_perp (поперёк рукава) | 55 | ширина полосы плотности |
| σ_par (вдоль дуги) | 40 | размытие места кластера |
| σ_z(r) = 22·(1 + r/1400) | 22 → 36 | толщина диска с flare |

### 1.2 Балдж (ядро)

Топ-64 кластера по **массе** `mass = member_count · (1 + mean_importance)` → трёхосная гауссиана `N(0, diag(90, 90, 65))`, минимальная дистанция между местами 25. Смысл: балдж = хабы знаний — самые связанные кластеры в центре, их рёбра к рукавам читаются как «мосты ядра».

### 1.3 Гало (одиночки)

Только **полностью изолированные** гранулы (без cluster_id, без резолвленных рёбер — их при средней степени узла ~12 немного, сотни). Радиальное распределение — Пламмера (честная астрофизика звёздного гало):

```
ρ(r) ∝ (1 + (r/r_p)²)^(-5/2),  r_p = 600
инверсия кумулятивной массы:  r = r_p · u^(1/3) / sqrt(1 − u^(2/3)),  u ~ U(0.05, 0.98)
направление изотропное, клип r ≤ 1600
```

## 2. Население: кто куда садится

### 2.1 Граф кластеров и порядок вдоль рукавов (ключ к коротким рёбрам)

Требование «соседство в БД ≈ соседство на карте» решается **спектральным упорядочиванием**:

1. Строим граф кластеров: вершины — 1753 кластера Level 2 **+ виртуальные кластеры** (компоненты свободных гранул размера ≥ 2 — «ассоциации»), рёбра — агрегированные рёбра гранул (вес = Σ weight). Свободная гранула с рёбрами в кластеры — не отдельная вершина, она «спутник» (§2.3).
2. **Fiedler vector** (собственный вектор лапласиана при втором минимальном собственном значении) даёт порядок вершин, минимизирующий сумму длин рёбер на прямой — связные кластеры встают рядом. `scipy.sparse.linalg.eigsh` на 1753×1753 — <1 с.
3. Порядок режется на 4 сегмента — **по 4 минимумам межсоседней связности** (минимальные «разрезы» кольцевого порядка, не тупо пополам) — это начальные углы рукавов. Изолированные в графе кластеров (нет межкластерных рёбер) досеиваются равномерно по рукавам детерминированно (seed от cluster_id).
4. Ранг внутри сегмента → s ∈ [0,1] → θ_i = s·θ_max, место = точка спирали + джиттер §1.1.

Итог: межкластерные рёбра в основном идут вдоль своего рукава — короткие и читаемые; через ядро — редкие межармные «мосты».

### 2.2 Члены кластера

Член j кластера c (размера m): `x_j = центр_c + N(0, σ_cl)`, где

```
σ_cl(m) = 14 + 7·ln(max(2, m))    →  m=3: ~22 · m=10: ~30 · m=50: ~41 · m=200: ~52 (cap 60)
```

Кластер = «созвездие»-сгусток внутри рукава; рукав читается как полоса плотности из сгустков (волна плотности Лина–Шу).

### 2.3 Спутники (свободные гранулы с рёбрами)

Свободная гранула садится у **якоря** — кластера с максимумом Σ весов её рёбер к его членам (или виртуальной ассоциации): гауссово поле вокруг центра якоря `σ_field = 120` в плоскости, `σ_z_field = 60` по вертикали. Это «звёздное поле вокруг созвездия» — рёбра спутников короткие по построению.

### 2.4 Локальная релаксация (внутри групп, опционально-обязательная)

После посадки — 40 итераций spring-electrical релаксации **только внутри каждой группы** (кластер/ассоциация, без глобальной репульсии — глобальную структуру держит спираль):

```
F_i = k_place·(place_i − x_i)                        пружина к месту,      k_place = 0.35
    + Σ_e k_e·w_e·(x_j − x_i)/d                      притяжение рёбер,     k_e = 0.05
    + Σ_{j∈group} k_r·(x_i − x_j)/d³                 отталкивание (Ньютон), k_r = 400, cutoff 30
x += v·dt,  v = 0.85·v + F·dt,  dt = 0.3              демпфирование
```

Стоимость: Σ n_i² по группам (группы ≤ ~200) × 40 итераций ≈ единицы миллионов операций — копейки.

## 3. Детерминизм и стабильность («позиция навсегда»)

- RNG **перноудовый**: `rng_i = np.random.default_rng(xxhash32(node_id))` — джиттер каждой звезды воспроизводим в любом прогоне, даже после TRUNCATE. Два force-прогона дают побитово одинаковые координаты.
- Рабочее правило таски: `SELECT ... FROM memories m LEFT JOIN map_layout l ON l.node_id = m.id WHERE l.node_id IS NULL` — размещаются только новые. Существующие строки **никогда не пересчитываются** (даже если кластер пересчитался — звезда остаётся, где села).
- Полный пересев (`force=True`): `TRUNCATE map_layout` + прогон с нуля — только по явной команде Мастера. `rev` — поколение раскладки (v2 стартует с force-пересева, rev=2).

## 4. Инкрементальность: посадка новых гранул

Новая гранула (не в map_layout) садится без движения старых:

1. **Есть cluster_id, у кластера есть размещённые члены** → вокруг их центроида, `σ_cl(m)`.
2. **Новый кластер целиком** → если есть рёбра к существующим кластерам: рядом с самым связанным (`место якоря + N(0, σ_perp)`); иначе — детерминированный свободный s-слот на рукаве hash(cluster_id).
3. **Нет cluster_id, есть рёбра к размещённым** → взвешенный барицентр топ-3 соседей (вес = weight ребра) + джиттер `N(0, 25)` (z-джиттер ×0.5). Гарантия «не далеко и не в каше»: барицентр уже в населённой зоне, джиттер меньше межзвёздных дистанций.
4. **Полный одиночка** → гало (§1.3, свой seed).

Атомарность: один batch `INSERT ... ON CONFLICT (node_id) DO NOTHING` в транзакции; `rev` инкрементируется только при ненулевом числе вставленных строк (реальное изменение).

## 5. Псевдокод таски

```python
def layout_galactic(force: bool = False) -> dict:  # Celery-таска, beat-слот как у layout_map
    nodes, edges = load_graph()          # memories(id, namespace, cluster_id, importance)
                                          # + relations (target_id IS NOT NULL, weight)
    if force:
        truncate_map_layout()            # только по команде Мастера
    placed = load_placed_ids()            # SET node_id
    todo = nodes - placed                 # LEFT JOIN IS NULL, векторно
    if not todo:
        return metrics(empty=True)

    # 1) граф кластеров: реальные clusters + виртуальные ассоциации (компоненты свободных >= 2)
    cgraph = build_cluster_graph(nodes, edges)
    # 2) спектральный порядок + разрез на 4 рукава по минимумам связности
    order  = fiedler_order(cgraph)        # scipy.sparse.linalg.eigsh
    arms   = cut_into_arms(order, n_arms=4)
    # 3) места: балдж топ-64 по массе; рукава по рангу; ассоциации — как кластеры
    places = assign_places(cgraph, arms)  # лог-спираль + гауссы §1.1
    # 4) члены кластеров вокруг центров; спутники к якорям; одиночки — Пламмер
    coords = place_members(nodes, todo, places, seed_per_node=xxhash32)
    # 5) локальная релаксация внутри групп (§2.4), только по todo-группам
    coords = relax_local(coords, edges, groups, iters=40)
    # 6) атомарная вставка новых — старые не трогаем
    upsert_ignore(map_layout, coords)     # ON CONFLICT DO NOTHING, batch 5000
    bump_layout_rev(changed=len(coords))
    return metrics(nodes=len(coords), took_s=..., arm_balance=..., edge_median=...)
```

## 6. Производительность (15.1k узлов / 104k рёбер)

| Шаг | Оценка |
|---|---|
| SQL: узлы + рёбра + placed | ~1 с |
| Граф кластеров (агрегация) | ~0.3 с |
| Fiedler (eigsh, 1753×1753) | < 1 с |
| Посадка векторно (numpy) | < 0.3 с |
| Локальная релаксация (40 ит.) | ~3–5 с |
| UPSERT 15k батчами | ~0.5 с |
| **Холодный старт (force)** | **~10–20 с** |
| Инкрементальный прогон (сотни узлов) | ~1–3 с |

Против DrL (минуты + сегфолт) — порядок выигрыша. Зависимости: numpy (есть), scipy (добавить в requirements, если нет), xxhash или встроенный hash-сид.

## 7. Интеграция (ничего в API не меняется)

- Таска `layout_galactic` занимает beat-слот `layout_map`; `force` — ручной запуск (MCP/CLI-обёртка по команде Мастера). Старый DrL-путь удаляется вместе с изоляцией-щитом после приёмки v2.
- `build_map_snapshot` читает `map_layout` как раньше — снапшот, `ETag`, `layout_stale`-бейдж, dirty-bump от reconciler/refresh_clusters — без изменений.
- Миграций нет (таблица 024 уже есть). Первый запуск v2 — с `force=True` (снос сферы).
- Prometheus: `galactic_layout_seconds{mode=full|incremental}`, `galactic_layout_placed`, `galactic_edge_median_len` (см. приёмку).

## 8. Приёмка (Катерина) — численные критерии

1. **Стабильность:** два force-прогона → SQL-diff координат = 0 строк (перноудовые сиды).
2. **Инкрементальность:** вставить тест-гранулу → инкрементальный прогон → старые строки не изменились (updated_at не дёрнулся), новая в радиусе ≤ 2·σ от центроида соседей.
3. **Структура (красота, измеримо):** медианная длина ребра ≤ 150 (при R_disk 900); доля рёбер длиннее 600 (межармные) ≤ 5%; разброс массы по рукавам ≤ ±20% (нет «пустого рукава»); z-разброс диска: 95% кластерных узлов в |z| < 3σ_z.
4. **Перф:** таска полного пересева ≤ 30 с; инкремент ≤ 5 с (на прод-воркере).
5. **Визуальная приёмка:** скриншоты трёх ракурсов Мастеру (сверху/под углом/с ребра — виден тонкий диск).

## 9. Фазы

| Фаза | Что | Кто | Объём | Время |
|---|---|---|---|---|
| **GL-1 Ядро** | кластерный граф + Fiedler-порядок + порез на рукава + места (балдж/рукава/гало) + посадка + перноудовые сиды + UPSERT; `force` | Сона | ~380 py + ~150 тестов | 2 д |
| **GL-2 Полировка** | спутники/ассоциации, локальная релаксация §2.4, метрики структуры, инкрементальные правила 1–4 | Сона | ~220 py + ~80 тестов | 1–1.5 д |

## 10. Риски

| Риск | Митигация |
|---|---|
| Fiedler на гигантской компоненте даёт «слитый» порядок | проверяется на живом корпусе в GL-1 (метрика edge_median до релаксации); запасной вариант — жадный insertion-тур по графу кластеров |
| Кластеры малого размера (средний 3.5) сливаются в полосу | это и есть рукав-волна плотности (Лин–Шу) — фича; σ_cl(m) логарифмический, чтобы большие кластеры не раздувались |
| Швы между рукавами (порез порядка) | разрез по минимумам связности; межармные рёбра через балдж — читаемые «мосты», метрика хвоста ≤ 5% |
| Пересчёт кластеров (refresh_clusters) меняет cluster_id — а звезда уже сидит | правило §3: размещённые никогда не двигаются; новые члены кластера садятся к текущему центроиду размещённых — кластер «доращивается» на месте |
| Сферический fallback в таблице | первый запуск v2 — только force=True (пересев), иначе старая сфера останется навсегда |

## 11. Что увидит Мастер после GL-3

Четыре спиральных рукава с сгустками-созвездиями (кластеры Level 2), светящееся ядро-балдж из хабов знаний, редкое гало одиночек и спутниковые поля вокруг созвездий. Связи внутри рукавов короткие; при вращении (ПКМ) виден тонкий диск с flare; карта **всегда одна и та же** — у каждой звезды своя вечная позиция, новые гранулы прирастают к родственникам, ничего не перетасовывается.
